# GTCG 自动化测试

用真实 Edge/Chrome（CDP 驱动）打开**真实的 index.html** 跑断言，不依赖任何 npm 包。

> **教训 1**：早期版本用一个单独的 `harness.html` 复刻页面结构来测，
> 结果测试全绿但真人根本打不出牌 —— 因为 harness 和真实页面的 DOM/交互早已不一致。
> 现在所有测试都直接跑 `../index.html`，杜绝再次脱节。
>
> **教训 2**：测试里长期设着 `window.GTCG_FAST = true`（跳过动画延时），
> 于是所有 `fx*` 动效代码都被短路、从没被执行过。
> 后来 `fxShake` 收到带空格的 class（`"justAttack dr"`）会抛
> `InvalidCharacterError`，而它位于 `battle()` 内 → **攻击永远结算不了**，
> 测试却全绿。现在 W 组专门在关掉 FAST 的情况下跑一遍动效路径。

## 怎么跑

```bash
node tests/run.mjs        # 主自检：125 条断言（规则 / 界面 / 交互 / 组卡器 / 装备）
node tests/measure.mjs    # 量各区域矩形，检测区块重叠
node tests/mouse.mjs      # 真实鼠标事件验证出牌
node tests/deck.mjs       # 组卡器 + 对战卡组选择器 + 装备安装
node tests/soak.mjs 20    # 多回合对局压测（抓卡死 / busy 不复位 / 弹窗残留）
node tests/shot.mjs       # 摆一个中局场面并截图
```

## run.mjs 的分组

| 组 | 覆盖 |
|---|---|
| A | 关键词定义与规则书一致 |
| B | 对局准备（双方各填 1 张能量） |
| C–E | 战斗结算、战力归零击破 |
| F–G | 出牌 / 共鸣 / 冠军之剑 |
| H–I | 阶段不可回退、费用支付 |
| J | 单位卡渲染（名字 / 战力 / 徽章 / 疲劳） |
| K–L | 阶段门禁、AI 行为 |
| M–N | 布局：单行不折行、不溢出、棋盘尺寸 |
| O | 交互：单击只提示、拖拽出牌、抽屉、路由 |
| P | 双击放大看卡图 |
| Q | 阶段提示与「为什么不能攻击」 |
| R | 攻击端到端（真实 DOM 点击走完结算） |
| S | 守护：锁定、接战、横置、疲劳解除 |
| T | [响应]：使用 / 不使用 / 付不起 |
| U | 24 张卡逐张打出都不卡 |
| V | 各关键词触发路径 |
| W | **关掉 FAST 跑动效**（防「动效抛异常中断结算」复发） |
| X | 守护锁定：不能打本体 / 其它角色 |
| Y | 组卡器（槽 / 卡池 / 筛选 / 加减卡 / 满 40 提示 / 路由） |
| Z | 装备安装（装上 / 类型不符拒绝 / 专属共鸣） |

## 约定

- 测试会注入 `window.GTCG_AUTO`（自动应答弹窗）与 `window.GTCG_FAST`（跳过动画延时）；
  真实页面本身不含这两个钩子。
- 需要验证「真实弹窗」的用例（R / S / T / X 组）用 `freshReal()`：
  开局用自动应答过掉掷骰与选能量，之后置 `null` 走真实弹窗，并用 `drainModals()`
  把连环弹窗（攻击目标 → 响应询问 → 支付费用）逐个点掉。
- 每条用例都从 `fresh(阶段)` 开始，保证互不干扰（会关掉上一条留下的预览与弹窗）。
- 卡组状态存在 `localStorage`，测试会改到它；如需复位，在页面上点「恢复预设」。
